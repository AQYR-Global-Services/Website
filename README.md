# AQYR Global Services

Next.js App Router project that brings the existing bilingual AQYR website demo into a Next.js application while preserving its current pages, styles, language switch, and interactions.

## Run locally

```bash
pnpm install
pnpm dev
```

Open `http://localhost:3000`.

## Build for deployment

```bash
pnpm build
pnpm start
```

## Editing and previews

- Edit page text and bilingual copy in `content/*.html`.
- Edit shared styles in `style.css` and interactions in `public/script.js`.
- Use the local Next.js server for the main preview. The root HTML files are static preview copies, not the deployed content source.
- After an edit, run `pnpm sync:preview` to refresh those static copies.
- The Chinese/English button keeps the same URL and remembers the visitor's preference; a new visitor starts in English.
- The enquiry form only prepares a mailto draft. The visitor must send it from their email app.

Page content is rendered on the server rather than appended after loading. Public pages use descriptive, extension-free URLs. Root `.html` files are offline previews only; pre-launch route names and `.html` aliases are not redirected.

### Navigation and motion

The shared floating header stays available while scrolling and becomes more compact after the first section begins to move out of view. Anchor offsets leave room below it. The sponsorship page keeps its full content in the document: a sticky side directory on wide screens becomes a horizontally scrollable directory on smaller screens, with the current reading section highlighted.

The five-stage diagram on `/approach` describes professional, case-specific preparation. It cycles through 01–05 every three seconds while in view; selecting a stage also updates its bilingual explanation. A pause/play control is available, and playback pauses during mouse hover, keyboard focus, offscreen or hidden-tab states. Reduced-motion visitors start with playback paused. Automatic updates are not live-announced to screen readers; explicit selections are. The connecting lines draw in once. This is an explanatory diagram, not an automated assessment or a claim of AI-powered visa advice. Photo blending is limited to the homepage and individual-service hero images rather than applied throughout the site.

The diagram numbers and titles correspond one-to-one with the five detailed service steps: 01 initial discussion, 02 assessment and scope, 03 preparation plan, 04 case coordination, and 05 ongoing communication. The stages remain selectable without an extra explanatory hint above the diagram. The understated playback icon retains a 44px click target. Case experience keeps all seven narratives with readable occupation-based anchors; the hero offers business/individual shortcuts and a grouped sticky directory sits to the left of the case studies on wide screens. On smaller screens the directory scrolls horizontally, highlighting the current case. No copy-link buttons are used.

Long-form company and legal copy uses a narrower reading measure. Dark brand surfaces have a separate high-contrast keyboard focus colour, and enquiry fields have stronger boundaries without changing decorative dividers. The existing sensitive-information advice sits beside the enquiry textarea and is connected with `aria-describedby`; the mailto draft/self-send flow is unchanged.

Shared accessibility labels and editorial-photo descriptions use `data-aria-label-en` / `data-aria-label-zh` and `data-alt-en` / `data-alt-zh`. The language switch updates these attributes as well as visible copy. Proper names and brand artwork retain their names rather than introducing translated identities.

Decorative background motion pauses offscreen and in hidden tabs. Reduced-motion preferences disable the ambient animation and line drawing; without JavaScript, the diagram labels, first explanation and detailed service content remain readable. Keep these behaviours when adjusting effects in `style.css` or `public/script.js`.

## Search metadata

Page titles, descriptions and canonical URLs are defined in `lib/site.ts`; the sitemap and robots file are generated by Next.js.
When connecting a final domain, set `NEXT_PUBLIC_SITE_URL` to its HTTPS origin in Vercel and redeploy. Do not use a preview-deployment URL for this setting.

The shared link preview uses `public/share-cover.png`, the original AQYR logo and the name AQYR Global Services. Open Graph and Twitter image settings are in `lib/site.ts`.

The site-wide JSON-LD graph is maintained in `lib/structured-data.ts` and rendered by `app/layout.tsx`. It links the public brand to its legal entity, ABN/ACN, three offices, parent organization and Yuan (Leon) Gao. MARN 1793302 is an identifier of the person, not a company licence. Keep this data consistent with the visible company, contact and footer disclosures whenever registration or contact details change.

## Visa guidance maintenance

Employer sponsorship is split by audience: `/employer-sponsorship` focuses on business and role preparation, nomination coordination and employer responsibilities; `/sponsored-visas` focuses on the individual's background, employer situation and application preparation. Their 482/186 pathway, comparison and English-requirement content is maintained once in `content/partials/sponsorship.html`. Include markers are expanded on the server and in offline previews by `lib/content-source.mjs`; do not copy eligibility text into separate page templates. The four other individual visa guides remain in `content/visa-services.html`. All use server-rendered native accordions and the same-URL language switch, with Home Affairs sources and no public editorial-date labels.

The main navigation has four entries: Employer Services, Individual Services, About Us and Contact. Three native disclosure dropdowns contain the relevant routes and work without JavaScript. JavaScript adds desktop mouse hover, one-open-at-a-time behaviour, outside-click dismissal and Escape/focus handling. Mobile navigation uses click-to-expand groups. Sponsorship contact links preselect employer or individual enquiry identity; the mailto draft/self-send flow is unchanged.

Before publishing changes to eligibility guidance, recheck the linked official sources, update both languages and the check date, and run `pnpm sync:preview`. Income thresholds, visa charges and processing times are intentionally not hard-coded here. Exemptions, nomination requirements and the applicant's evidence still need a case-specific assessment; no outcome or invitation is guaranteed.

## Local media

### AQYR brand materials

`public/aqyr-logo.svg` is the supplied official full-colour RGB artwork, including its original viewBox and clear space. Header and footer dimensions account for that clear space; do not crop or stretch the mark to fill a previous asset's dimensions. The share-cover generator preserves the source viewBox. The primary colours remain Evergreen `#1f4434` and Jade `#45c487`; Pearl, Sage, Stone and restrained Teal accents follow the supplied June 2026 brand guidelines. English typography already uses Rethink Sans and Albert Sans. Decorative texture is CSS-only and does not introduce another remote resource.

The approved material adaptation is limited to pre-recruitment planning on `/employers#hiring-review`, individual assessment and preparation on `/approach`, and group resources on `/about`. Both languages describe shared group background and resources that can be accessed when needed, not current use of the group's AI tools in migration casework. No group executives, article statistics, software subscription terms or new case outcomes have been added. The supplied marketing articles are background reading, not evidence of visa eligibility or a promise of automated assessment.

Original portraits stay in `public/team/*.jpg`. The website uses responsive 240px and 480px WebP copies. Run `pnpm prepare:media` after replacing an original portrait or the logo to regenerate those copies and the share cover, then run `pnpm sync:preview`.

Editorial scene photos are stored locally in `public/scenes`, with responsive 640px, 960px and 1440px WebP copies generated by the same command. Their source pages, photographers and licenses are recorded in `assets/photography.json`. The active scenes show Melbourne architecture, an individual city-life perspective and a workplace; previous conversation assets are retained but are not displayed. These are illustrative photographs, not AQYR staff, clients, offices or case results. The homepage photo caption describes the team's case-by-case approach, not a software product or automated visa assessment. Site visitors do not depend on the stock-photo hosts for image loading.
